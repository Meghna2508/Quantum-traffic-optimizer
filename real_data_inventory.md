### Confirmed real data
- [benchmark_results.json](benchmark_results.json) and [benchmark_results.csv](benchmark_results.csv): confirmed real SUMO benchmark output generated by [run_benchmark.py](run_benchmark.py) on the optimize branch, commit 4e19435.
- The artifact includes 45 rows: 5 seeds x 3 scenarios x 3 controllers.
- Scores include queue, travel time, throughput, fuel, CO2, wall time, emergency travel time, and QAOA fallback/exec metadata.
- Provenance is explicit in the JSON metadata: branch=optimize, commit=4e19435, steps=200, interval=30, shots=512, maxiter=15.

### Derived data
- [simulation_performance_report.md](simulation_performance_report.md): summary tables and aggregate means derived from [benchmark_results.json](benchmark_results.json); no separate runtime evidence beyond that artifact.

### Mock/demo data
- [demo_results.json](demo_results.json): generated by [run_hackathon_demo.py](run_hackathon_demo.py) for a demonstration comparison; real output, but demonstration-oriented and not a benchmark dataset.
- [pareto.pkl](pareto.pkl): created by [pareto_sweep.py](pareto_sweep.py), which explicitly contains a deterministic mock solver and mock simulator; not real QUBO/QAOA output.

### Historical data
- [benchmark_results.json](benchmark_results.json) and [benchmark_results.csv](benchmark_results.csv) are historical results from the optimize branch, not from the current final-integration branch.
- The branch metadata in the JSON records that provenance explicitly.

### Missing data
- No final-integration benchmark artifact exists in the repository.
- No saved results for the script-defined Bottleneck and Incident scenarios were found in the stored benchmark exports.
- No raw QAOA call-by-call logs were saved beyond aggregate counts in the benchmark file.
- No per-step SUMO trace files were preserved as standalone result artifacts.
- No benchmark logs exist in .log or .txt format for the dataset listed above.

### Consistency checks
- CSV and JSON row counts match: 45 rows in both.
- Scenario names match between CSV/JSON and the runner: Normal, Congestion, Emergency.
- Seeds are present and consistent: 42, 43, 44, 45, 46.
- The benchmark metadata states 5 seeds and 3 scenarios, which matches the stored rows.
- The stored results do not include the later Bottleneck and Incident scenarios defined in [run_benchmark.py](run_benchmark.py).
- The branch in metadata is optimize, not final-integration; this is an explicit provenance mismatch with the current working branch.
- No evidence of duplicated runs was found in the benchmark files.

### Inconsistencies / caveats
- The current repository branch is final-integration, but the benchmark output was generated on optimize commit 4e19435.
- The benchmark runner defines five scenarios, while only three scenarios are actually saved in the exported artifacts.
- Real benchmark data exists, but it is not current final-integration evidence.

### Recommended single next experiment
- Re-run only one targeted benchmark on the current final-integration branch for a single scenario and single seed, with the exact same configuration used in the saved optimize results, to establish current-branch provenance. This is the minimum valid gap-filling step because all saved benchmark data is historical and branch-stamped to optimize.
